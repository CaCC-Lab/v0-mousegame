## 3. ユーザー判断が要る点

推奨を先頭に置いた。**UI/UX の変更は CLAUDE.md で無断変更が禁止されているため、D6 など画面が変わるものはここでの承認をもって許可とする。**

| # | 論点 | 選択肢（推奨が先頭） | 推奨の理由 |
|---|---|---|---|
| D1 | 0点のリザルトでランク（ブロンズ）を出すか | **① 0点ではランクを出さず「まずは 🍎 をクリックしてみよう」を出す**／② 今のまま出す／③ ランクを廃止 | 初見テストで「何もしなくてもブロンズなら段位の意味がない」「冷たい」。教育用途では0点の子に要るのは段位ではなく次の一手 |
| D2 | リザルトの「つぎの◯◯まで あと N てん」の基準 | **① 今回のスコア基準に変え、ベストは別欄に残す**／② ベスト基準のまま見出しを「ベストのだんい」に変える | 大きく出ている数字（今回のスコア）と「あと N てん」が別の数から出ていると矛盾に見える。②は最小変更だが、子どもには「ベスト」と「今回」の区別が要る |
| D3 | 難易度セレクタ（かんたん／ふつう／むずかしい） | **① 表示を実態（得点倍率のみ）に合わせ、起動画面から「せってい」の中に移す**／② 時間・果物数も本当に効くように実装する／③ セレクタを廃止 | ②はステージ表（6段）の設計と衝突し、計測なしに決められない。①は嘘を消すだけで遊びを変えない |
| D4 | 用語 | **①「コンボ」「ベスト」に統一。初出の場所に効果を添える（例「コンボ → てんすうアップ」）**／②「れんぞく」「さいこう」とひらがなに統一 | アーケードの説明文・ヘルプ・リザルトがすでに「コンボ」「ベスト」を使っている。変更箇所が最少 |
| D5 | アーケードの構造（2-1「遊び続ける理由」）をこの版で直すか | **① 直さない。v1.2 として別計画にする**／② この版で難化の段差か負け条件を足す | 構造は計測なしに決められない（6-9）。「伝わらない」を潰す前に演出や構造を盛らない（6-1）。混ぜると「何を直したか」が一文で言えなくなる |
| D6 | 起動画面に残すもの | **① プレイエリア内は「題名・モード2枚・はじめる」だけ。HUD の数値・難易度・うごくモード・言語・音量は「せってい」に畳むか、プレイ開始後に出す**／② 難易度パネルだけ畳む／③ 変えない | 1-3（タイトルの文字は3つ以内）と初見テスト E9。遊ぶ前の画面に遊んでいる最中の HUD が出ている |
| D7 | 右端のドロップ帯を常時表示するか | **① そのまま常時表示**／② スイカを掴んだときだけ強調する | ドラッグ先を最初から見せるのは練習ツールとして妥当。初見テストの指摘は「意味が分からない」なので、D4・D6 の文言整理で足りるか先に見る |
| D8 | ブラウザ言語が日本語でも英語でもないときの言語 | **① 英語**／② 日本語のまま | CrazyGames の要件（英語フォールバック）。日本語話者には影響しない |
| D9 | ミス時の効果音を足すか | **① 足さない**／② 柔らかい音を足す | 小学生向けで、誤操作を音で責める形になりやすい。ミスヒントの文字で足りているかは G1 修正後に見直す |

## 4. 進め方の決めごと

1. **仕様の単一ソースを先に作る。** 本リポジトリには `shared-context.md` に当たる文書が無いので、T2 で `docs/game-spec.md` を新設する（モード・操作・得点・コンボ・フィーバー・パワーアップ・難易度・用語表）。**D の判断を反映してからコードを直す**。以後、`HelpDialog`・`translations.ts`・ストア原稿の数値は、この文書か `types/*.ts` の定数から引く
2. **TDD**: 各タスクは失敗するテストを先に書く（プロジェクト CLAUDE.md）。G の測り方がそのままテストになるよう書いてある
3. **PR 必須・master 直 push 禁止**。PR の単位は `v1.1-tasks.md` の「PR」列
4. **目標値が仮のもの（G7）は、最初の計測の後に決め直してよい。決め直した値と理由は残す**（6-9）
5. 段5の最後に G1〜G17 を1つずつ測り直して ○× を付け、残作業を記録する
6. 新しく分かったことのうち**他のゲームでも効くことだけ**を `20260923-browser-game-design-knowhow.md` に戻す（段6）
